### Guest chats: a guest's own Claude (2026-10-09)

When the owner switches guest chats on (Worker variable `CHAT_GUESTS_ENABLED=1`), the **Claude** item in the sidebar also appears for every signed-in hub member (the Worker's `/auth/session` now says `chat: true`; `themes.js` keeps it in `Theme.who` and `shell.js` shows the item for the owner or `chat === true`). A guest's chat is **their own Claude on their own computer**: the page has a **Connect your Claude** panel (download the runner, make a key, see whether the computer is connected, revoke a key); chats are read-only (no Read/Edit switch); the pill and messages say "your Claude", not "the runner".

- **The download** is `guest-runner/guest-runner-<8 hex>.zip` plus `guest-runner/guest-runner.json` (`{file, sha256, bytes, files}`), shown with its SHA-256. The name carries the checksum so a new build is a new address and the CDN cannot serve a stale one against a new checksum; the page accepts the manifest only in exactly that shape (`parseKit`). Regenerate it after any change to ClaudeRepo's `runner/`: `node runner/tools/pack-guest-kit.mjs <this repo>/guest-runner` (it deletes the old zip). `test/chat.test.js` checks the zip against the manifest, that it holds no secret, and that only the current zip is kept.
- A key is shown **once**, in a read-only field with a Copy button; the list shows name, state, expiry and last use, never the key. Making and revoking need a recent sign-in (the Worker enforces it).
- `privacy.html` says what a guest's chat is: stored in the guest's own space, answered on their own computer with their own Claude account, no Claude token sent to or kept here.
- Tests: `node test/chat.test.js` (28) and `node test/session.test.js`. The same `shell.js` and `themes.js` change is in study-hub and campaign-hub (and market-dashboard) so the link shows everywhere.

### Cache tags: a deploy is never hidden behind Cloudflare's cache (2026-10-09)

Cloudflare keeps static files (scripts, stylesheets) for hours, so after a deploy a browser could keep running yesterday's script. Every local script and stylesheet link in the pages now names its file by content, e.g. `chat.js?v=9df75216` (the first 8 hex digits of the file's hash, line endings ignored). A changed file is a new address and is fetched at once; an unchanged one stays cached.

**After changing any script or stylesheet, run `node tools/stamp-assets.js`** (it rewrites the links; `--check` only reports). `test/cache-tags.test.js` fails if a link is missing or stale, so a forgotten stamp is caught before it ships. Tests: 7 new.

## Ops board items: briefing, steps and approvals (2026-10-22)

Opening an item shows, top to bottom: **a decision panel** when something waits for you (the question, a note box, Approve and Reject; Claude reads the note and acts on it), **the actions that are yours** as a numbered list you tick off, then **What this is**, **Where it's at**, the whole **plan or steps** (each marked You or Claude), the **details**, and the change log. The edit form is folded under "Edit this item" and has the new fields: What this is, Where it's at, Question for you (fill it in to ask for a decision) and Steps (one per line: `[ ] you: Delete the DNS record`). Tiles show "Decision needed", "2 actions for you", `1/5 steps` and, after you answer, "Approved, Claude to pick up". The pure helpers are in `ops.js` and tested in `test/ops.test.js`; the Worker side is described in ClaudeRepo's `cloudflare-worker/README.md` (Ops Board).
