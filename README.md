# barnyard-hub
Personal hub: widget-grid landing page linking out to other web apps.

## History

- **2026-08-19** — Went live at farmerbarnyard.github.io/barnyard-hub/: widget-grid hub with a Stocks tile (Cloudflare Worker-backed live-price ticker) linking out to market-dashboard, plus placeholder tiles for future projects.
- **2026-08-19** — Claimed `dashboard.barnyard.site` as this repo's GitHub Pages custom domain. That domain previously belonged to market-dashboard, which has moved to `stocks.barnyard.site`; the Stocks tile's link was updated to match.
- **2026-10-07** — Added the **Ops board** (`ops.html`, `ops.js`, `ops.css`): a private, live progress tracker for the projects on this account, replacing the Notion progress pages. Four lanes (In progress, Soaking & monitoring, Waiting on you, Backlog), stat tiles, filters, a "Coming up" list, a Proposals tab, and tiles that open a detail drawer with edit controls and a change log. Every change is pushed over a WebSocket from the Worker's `/ops/*` routes, so tiles move the moment anything changes. Needs a login in the `barnyard-hub-sso` group (see ClaudeRepo's `cloudflare-worker/README.md`, "Ops Board setup"). The placeholder "Coming soon" tile on the landing page is now an **Ops** tile linking to it (with a one-line summary for logged-in viewers, `ops-tile.js`). Helper tests: `node test/ops.test.js`.
- **2026-10-08** — Redesigned the hub as a dashboard with a shared shell. Every page now sits in a left sidebar (Overview, Ops board, and links to Study, Campaign and Stocks) with a top bar (search that jumps to pages and board items, a light/dark switch, Settings). The Overview opens with a plain sentence ("Three things need you."), the *Waiting on you* list with **Mark done** and **Undo**, and a *Since you last looked* feed from the Ops board's change log; the weather, week, to-do and live-price widgets are unchanged underneath. **Settings** (sliders button) holds 18 colour themes, light/dark/match-device, 18 page backgrounds with a strength control, comfortable/compact density, a full or icons-only sidebar, the Overview's widget layout (show, hide, width, order, three presets), and the Ops board's default view and backlog folding. Everything applies as you choose it. The Ops board gained a list view, a folded backlog, a banner and disabled editing when the connection drops, `ops.html#it_xxxxxxxx` deep links, and a flatter look.
  - New files: `themes.js` (themes, settings, validation, the shared look-and-feel cookie), `shell.js` and `shell.css` (the shell and the shared styles), `overview.js` (the Overview page), `fonts/` (Bricolage Grotesque, IBM Plex Sans and Mono, served from this repo because the CSP blocks Google Fonts). `style.css` and `ops-tile.js` are gone. `auth-gate.js` and the widget scripts are untouched.
  - Choices are saved in this browser (`barnyard-settings`). The look-and-feel keys (theme, mode, background, strength, density, sidebar) are also written to a `bh_prefs` cookie on `.barnyard.site` so the other sites can match; it carries no identity and every value read back from it is checked against the allowed lists.
  - Like `auth-gate.js`, `themes.js`, `shell.js`, `shell.css` and `fonts/` are meant to be **hand-copied unchanged into the other sites' repos** (none has a build step).
  - The Overview's feed reads `GET /ops/recent` from the Worker; until that route is deployed it falls back to each item's last-changed time.
  - Tests: `node test/themes.test.js` (18 themes readable in light and dark, every background has CSS, settings and cookie validation, the pages stay inside the CSP), `node test/overview.test.js`, plus the existing `test/ops.test.js`.- **2026-10-07** — Settings are now saved to the signed-in user's **profile**, so a look chosen in one browser loads in any other.
  - The Worker's `GET/PUT/DELETE /prefs` (ClaudeRepo PR 303) keeps one copy per login. `themes.js` does the syncing (`BarnyardTheme.sync`); `shell.js` only shows its status in the Settings footer.
  - The browser stays the fast path: settings apply instantly from this browser, then sync after sign-in. Changes upload about 1.5 s after the last one; a profile saved elsewhere is applied when the tab opens or regains focus. Last write wins, but the first time an account is seen on a browser its saved profile wins, with a "Keep this browser's" button on the toast. A browser that was never customised never uploads, so it cannot overwrite a profile.
  - Signed out (or off barnyard.site) nothing is sent; the footer offers **Sign in**. **Remove saved profile** in the footer deletes the server copy; this browser keeps its look.
  - Sync state is in localStorage `barnyard-sync` (revision, one-way account label, unsent changes). Same hand-copied files as before (`themes.js`, `shell.js`, `shell.css`), no new file.
  - Tests: `node test/profile-sync.test.js` (25 cases against a fake fetch, storage and timers).
- **2026-10-08** — **Own board and own Claude for each signed-in person** (hub side of the multi-board work; Worker side is ClaudeRepo PRs 304-306).
  - A guest (anyone signed in who is not the hub owner) now lands on **Create your board** instead of the owner's. One click makes their board (with a "Connect your Claude agent" starter item); the Overview shows a matching card until they do. If a board is switched off by the owner, both pages say so.
  - **Connect your Claude** panel above their board (`agent-setup.js`): make an agent key (shown once, with the exact commands for Windows or macOS/Linux, key filled in), give Claude the brief, and paste the "fill my board from my projects" prompt. It shows "Your Claude is connected. Last update 2 min ago." as soon as the first update arrives (polls while in view, catches up when the tab returns). **Settings, Agent access** lists the keys (up to 3) with Revoke and Add.
  - **`agent-kit/`** (public, static, no secrets): `ops-board.ps1` and `ops-board.sh` helpers (tested against a mock API for every command, quoting, Unicode and error cases), `agent-brief.md`, `populate-prompt.md` and a README. The panel fetches the brief and prompt from there.
  - The owner is unaffected: no panel, no tab, same board, same token. The whole feature stays off until the Worker secret `OPS_OWNER_SUB` is set.
  - Tests: `node test/agent-setup.test.js` (18: state and wording, the install commands refuse anything that is not exactly a key, and the brief, scripts and README stay consistent with each other).
- **2026-10-08** — **What a guest does not see** (hub side of "who is signed in"; needs the Worker's `owner` and `apps` fields from ClaudeRepo PR 304).
  - `themes.js` now also reads `/auth/session` (`BarnyardTheme.who`): signed in or not, hub owner or not, and which apps their groups allow. It is a display hint only; every route still checks its own group. It **fails open**: if the answer is unknown (signed out, error, offline) nothing is hidden. A signed-in answer is kept in `sessionStorage` for a minute.
  - `shell.js` hides the **Study** and **Campaign** links (and their jump-search results) from a signed-in person whose groups don't include them. Stocks stays for everyone. The hub owner always sees all.
  - `overview.js` hides the **This week** and **Shortcuts** widgets (the owner's calendar and links) from a signed-in person who is definitely not the owner, and leaves them out of Settings, Home layout. `glance-widgets.js` skips the calendar call for them instead of letting it fail.
  - The same three shell files (`themes.js`, `shell.js`, `shell.css`) are copied unchanged into Study, Campaign and Stocks, so the links behave the same everywhere.
  - Tests: `node test/session.test.js` (13: the rules, loading, caching, failing open, and the widget restriction).
- **2026-10-08** — **Settings, Account** (hub only): shows a signed-in person their own account id with a Copy button, but only until per-person boards are switched on. The hub owner copies it into the Worker secret `OPS_OWNER_SUB`, which is what turns the multi-board behaviour on (see ClaudeRepo's README, "Owner identity"). Once the secret is set the tab just says whether you are the owner or a guest. The id is read from `/auth/whoami` and is not a credential.
