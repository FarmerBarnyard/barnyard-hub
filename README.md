# barnyard-hub
Personal hub: widget-grid landing page linking out to other web apps.

## The Overview board

The Overview's tiles can be moved and resized independently. Press **Customise** above the board; **Done** saves, **Cancel** puts everything back, **Reset layout** returns to the standard arrangement (it asks first).

- **Move:** drag a tile by its top bar. A dashed outline shows where it will land and the other tiles flow around it. Tiles always float up, so there are no accidental gaps.
- **Resize:** pull the right edge, the bottom edge or the corner. Each tile has a smallest and largest size; its content adapts to the room it is given and scrolls inside the tile if it needs more (**Fit to its content**, in the tile's options menu, makes it exactly as tall as its content).
- **Keyboard:** Tab to a tile's top bar, press **Space** or **Enter** to pick it up, move it with the arrow keys, resize with **Shift** and the arrow keys, **Enter** drops it, **Escape** cancels. Each tile also has an options menu (Move left, right, up or down, Make wider, narrower, taller or shorter, Fit to its content, Hide). Everything is announced to screen readers.
- **Tiles:** hide a tile from its menu, or tick and untick tiles in the **Tiles** panel, which also describes each one.
- **Narrow screens:** from 960px wide the board is 12 columns; from 560px it is the same layout in 6 columns; below that a single column in reading order. Customise on a narrow screen edits that single list (Move earlier or later, Taller or Shorter, Hide); dragging and resizing are for wide screens.
- **Where it is saved:** in your profile settings, as `board` (the tiles' places and sizes), so it follows you to other browsers; which tiles are shown stays in `widgets`. The browser keeps a copy so the page draws at once. Choosing a preset or changing widths or order in Settings, Home layout starts the arrangement over from that list (it clears `board`). Anyone who has never customised sees the same arrangement the page always had.

For developers: `board-layout.js` is the pure layout engine (12-column grid, tiles `{id, x, y, w, h}` that never overlap and float up; `move`, `resize`, `nudge`, `grow`, `remove`, `add`, `reorder`, `toColumns`, the saved shape) with `test/board-layout.test.js` (random operations from a fixed seed); `board.js` is the page code (grid placement, the Customise bar, drag, resize, keyboard) with `test/board.test.js`; `board.css` is its styling. **To add a tile (the registry, stable):** a tile is its own file that calls `BarnyardTiles.register({ id, title, about, w, h, minW, minH, maxW, maxH, ownerOnly, permission, render(container, ctx) })` (`tile-kit.js` provides it; `tile-assets.js` is an example). `id` is lowercase letters, digits and hyphens (up to 32); `w`/`minW`/`maxW` count the 12 grid columns and `h`/`minH`/`maxH` count rows (36px each; at most 12 columns and 40 rows); `ownerOnly` hides it from signed-in people who are not the owner; `permission` (optional, e.g. `assets.view`) hides it when the session's `permissions` list exists and does not include it, and is ignored while that list is absent. `render` draws into `container` (`ctx` is `{board: true}`) and may return `{refresh(), destroy()}`; the board calls it only the first time the tile is shown. Load `tile-kit.js` and the tile's file in `index.html` before `overview.js` (and `tiles.css` if it needs it). A registered tile is not in the widgets list: it starts hidden, shows up in Customise, Tiles, and once ticked and saved lives in `board` only. The older eight widgets are plain sections on the page: add the id to `WIDGET_IDS` and `DEFAULT_WIDGETS` in `themes.js` (a shared file: copy it unchanged into the other three sites) and to `WIDGET_TITLE` in `overview.js`, and give it a starting size and limits in the `CATALOGUE` of `board-layout.js`. A tile with no catalogue entry still appears, at a middling size. The Worker accepts the saved board in `/prefs` (ClaudeRepo `src/prefs.js`: at most 16 tiles, whole numbers on the grid).

- `privacy.html` says what a guest's chat is: stored in the guest's own space, answered on their own computer with their own Claude account, no Claude token sent to or kept here.

### Cache tags: a deploy is never hidden behind Cloudflare's cache (2026-10-09)

Cloudflare keeps static files (scripts, stylesheets) for hours, so after a deploy a browser could keep running yesterday's script. Every local script and stylesheet link in the pages now names its file by content, e.g. `chat.js?v=9df75216` (the first 8 hex digits of the file's hash, line endings ignored). A changed file is a new address and is fetched at once; an unchanged one stays cached.

**After changing any script or stylesheet, run `node tools/stamp-assets.js`** (it rewrites the links; `--check` only reports). `test/cache-tags.test.js` fails if a link is missing or stale, so a forgotten stamp is caught before it ships. Tests: 7 new.

## Day planner: the Plan view and the Today's plan tile (2026-10-28)

It proposes how today's and this week's to-dos fit around your calendar, and re-plans when something slips. **It only suggests.** Nothing is stored until you press **Accept**, and nothing it does moves an event, a Google Calendar entry or a block you pinned.

- **How the plan is made** (`planner-engine.js`, `test/plan-engine.test.js`; no model, nothing hidden): the most overdue first, then earliest deadline first with a two-day nudge for priority (high counts as due 2 days sooner, low 2 days later); to-dos with no date go after dated ones.
