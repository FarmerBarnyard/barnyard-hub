What changes in the real site

A look is a switchable layer. The colour themes, backgrounds, density and sidebar choices you have today stay exactly where they are and keep working.

The Look choice

  • Settings gets a new Look choice (a list of looks). It is saved in your profile and in the shared bh_prefs cookie, like the theme, so it follows you across the Dashboard, Study, Campaign and Stocks.
  • themes.js sets data-look="..." on the page, the same way it sets the theme. The default stays the current look until you change it.

Two kinds of look

  • CSS look layer only. A new stylesheet (for example look-plain.css) loads when the look is chosen and restyles the existing page structure. This is the cheap kind. P and D are closest to it, and A probably (that one is my reading, not a designer's). Every other look needs at least a second page chrome from shell.js in place of the sidebar.
  • Needs its own renderer. The look changes the markup of the Overview, so a CSS layer is not enough. A renderer script reads the same data and draws it. The designers say this is the case for J (Day Line), K (Lines) and L (Grid 9), and their specs describe renderers or per-page layouts for G, H, I, M, N and O too (I is a character-grid renderer, the heaviest). My reading for B, C, E and F: they rearrange the Overview, so they need renderers as well.

Themes, backgrounds, density, sidebar, per look

  • Every look is built on the same 12 colour values the themes already define (plus the three status colours), so all 18 themes work in light and dark.
  • Backgrounds work everywhere, but where a look draws an opaque sheet the background only shows in the margins. Each look lists which backgrounds suit it and which clash (see the table).
  • Density maps to row padding and type size in every look.
  • The sidebar setting (full or icons) has no meaning in looks without a sidebar (B, C, E, F, H, I, J, K, L, M, N, P). The setting stays saved and is greyed out in Settings while such a look is on, so switching back restores it.

Shared across the four sites

The shell files (themes.js, shell.js, shell.css, fonts) are hand-copied identically into Study, Campaign and Stocks (node tools/sync-shell.js). A look is one more pair of files (CSS and, for some looks, a renderer script) copied the same way, with cache tags bumped. Pages whose own scripts build tile grids (Overview, Monitoring, Calendar, Vulnerabilities) each need a small variant per look that is not CSS-only.

Contrast test

test/themes.test.js checks six pairs per theme today. Each look adds the pairs it draws (for example muted text on the selected row, status colours as text, the accent as a fill) across all 36 theme and mode combinations. Two weak spots exist in the current themes: Amber light (accent as text on the page: 4.38 to 1) and Dusk dark (muted text on a selected row: 4.46 to 1). The looks avoid using them that way, except A and C where links use the accent: they need an ink-and-underline fix on Amber light.
