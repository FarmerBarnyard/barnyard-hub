# Look N: Prompt

Mock-up: `N-prompt.html` (preview picture: `N-prompt-preview.png`). Generated by `_gen-MNO\build.ps1` from the site's real themes, backgrounds and fonts.

## Rationale
Most days the administrator already knows what they want: go to a page, find an item, do a thing. The dashboard's real job is to surface the few items that need a decision. Prompt answers "what do you want to do?" first, with one big input, and puts the list of things that need doing right under it. Pages are commands, not destinations: you type "ops" or click "Ops board". The overview is only what needs you, the systems that are not up, and a short history. There is almost no chrome, so a failing system or an overdue item is the loudest thing on the page. It is keyboard-first (type, Up and Down, Enter, Esc, "/") but every row is also a plain clickable button, so mouse users lose nothing.

## Layout rules (what replaces rounded cards and accent rails)
- One column, about 880px, left aligned and set in from the left edge (not centred). The column has a solid page colour; backgrounds show only in the margins.
- Top line: product name, date, one sentence of system state with a link to the failing system.
- The input: 32px mono (26px compact), underlined by a rule that darkens on focus. Placeholder "go to, find, do".
- Page navigation is a plain row of words under the input ("go to  Overview  Ops board  Monitoring ...") so mouse users always have it. The current page is bold with an underline.
- Every list is ruled rows: verb | label | hint. The verb (approve, sign off, choose, check, open, go to) sits in a left column in small mono; the hint (due date, state) is right aligned. A selected or hovered row gets a soft tint, not a rail or a pill.
- No cards, no tiles, no icons. Section headings are bold sentence-case words with a quiet count.

## Type
- Input and verbs: IBM Plex Mono (500 for the input, 400 for verbs). Mono is used because this is a command line and verbs are command names, not for decoration.
- Everything else: IBM Plex Sans 400 and 600, 16px (14px compact).

## Icon approach
None. The verb is the icon: "approve", "sign off", "run". State is a word ("down no reply for 14 min", "degraded last good 03:10"); the failing verb ("check") is coloured with the status red and also carries its word. Keyboard hints are small bordered key labels.

## Tone of voice (5 rewrites)
| Today | Prompt |
|---|---|
| Waiting on you | Do now (4 need a decision) |
| Since you last looked | Recent, your commands and what happened |
| Open the board | go to Ops board |
| Mark done | do: mark done it_a1 |
| The board is private. Log in | Sign in first: type "sign in" |
Rules: imperative verbs; the first word says what will happen; no filler ("Approve renewal: barnyard.site domain", not "You might want to approve..."); an empty search says what to try ("No command matches 'xyz'. Try 'go to ops', 'find backup' or 'check app02'.").

## AI clichés avoided
Card grid, big-number tiles with gradient, accent rail, small-caps eyebrow labels, emoji, icon beside every item, centred hero, chatty headings, near-black with one acid accent (colour comes from the user's theme and is used for state words and the selection tint only).

## Backgrounds
Because the column is opaque, a background shows only at the sides (large screens) and not at all on phones.
- Suit: all of them, best Grid, Dots, Blueprint, Contours, Radar, Rays, Horizon (patterns frame the column like graph paper beside a terminal).
- Clash: none read as unreadable, since text never sits on a pattern. Aurora and Mesh at strong strength make the margins loud next to a quiet column.

## What it would change in the shared shell
- `data-look="prompt"` on `<html>`, a `look` setting in themes.js (validated, in the cookie and profile sync).
- shell.js replaces the sidebar with the top line, input and "go to" row. Needs a small command registry built from data the page already has: menu items, the Ops board items (already fetched by overview.js), service states (already fetched), and a few actions (mark done, add item, open Settings). No new API.
- Keyboard handling: "/" to focus, listbox roles (`role="listbox"`/`option`), `aria-selected`, `aria-live` for the result line, Esc to clear. Focus must return sensibly after navigation.
- Pages whose content is not a list (Calendar grid, Projects timeline, Monitoring charts) keep their native content under the same input: the look is a hybrid there (input and "go to" row on top, the page's own body below). That is a compromise to state to the owner.
- The sidebar setting is not used in this look.

## Sidebar setting
Not applicable: no sidebar. The "go to" row replaces it and wraps on narrow screens. Settings for `full` and `icons` are kept (so switching back to another look restores them).

## Contrast (36 combinations, tokens from themes.js, `_gen-MNO\contrast.ps1`)
- A real failure was found and fixed: hint text (due dates) in `--fg-dim` on the selected row's tint measured 4.42 (Azure light), 4.45 (Steel light) and 4.43 (Arctic light). Hints on the selected or hovered row now use `--fg` (9.46 at the lowest, Stone light). After the fix no pair fails.
- Lowest ratios: text on page 10.76 (Stone light), strong text 15.46, hints and placeholder on page 5.04 (Arctic light), strong text on the selected row 13.59, the failing-system verb (status red) on page 4.93 (Stone light).
- The accent token is never used as text.

## Effort estimate
8 to 10 Engineer days: shell layout and input 1.5, command registry and matching 2, keyboard and accessibility 1.5, Overview and Ops list renderers 2, hybrid handling of non-list pages 1.5, 36-combination test, keyboard tests and review 1.5. It is the most opinionated look and the one that changes the most behaviour.

## Open doubts
Command-first suits an owner who remembers page names; a new guest user may not. The "go to" row mitigates this. The mock-up's actions (approve, sign off) only log a line; real actions need the existing confirm steps (strong sign-in for sensitive ones). Text typed into the input could contain private words: nothing is sent anywhere, matching is local.
